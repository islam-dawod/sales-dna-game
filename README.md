# 🧬 SALES DNA GAME

**نظام لعبي (Gamified) لتشخيص أنماط المبيعات، مقارنة الموظفين، وفحص تطابق المرشحين الجدد.**
*מערכת משחקית לאבחון, השוואה וגיוס אנשי מכירות.*

> Game + Assessment + Sales Analytics — لا يشعر المستخدم أنه في اختبار، بينما تبني المنظومة خلف الكواليس بروفايل مبيعات كامل وتقارنه بالموظفين الناجحين في الشركة.

## 🎮 التجربة (3 مسارات)

| المسار | الوصف | ما يراه المستخدم |
|---|---|---|
| 🧑‍💼 **موظف حالي** | دخول بكود الموظف → 7 مراحل / ~38 سؤالاً | شخصيته في المبيعات + XP (النتائج التفصيلية للمدير) |
| 🚀 **مرشح جديد** | تسجيل → المرحلة 1 (16 سؤالاً) → تطابق أولي → المرحلة 2 (~21 سؤالاً) | «انتهى التحدي» فقط — بدون أي نتيجة أو تطابق |
| 🧠 **مدير** | كونسول تحليلي كامل (PIN تجريبي `1234`) | كل شيء |

### مراحل اللعبة
`LEVEL 1 TARGET HUNTER` → `LEVEL 2 REJECTION ZONE` → `LEVEL 3 DISCIPLINE MODE` → `LEVEL 4 LEARNING LAB` → `LEVEL 5 RESPONSIBILITY TEST` → `LEVEL 6 COMMITMENT ZONE` → `LEVEL 7 FINAL SALES BATTLE`

كل مرحلة لها شخصية مرافقة (REX / NOVA / MAX / ZEN / LEO)، شريط تقدّم، XP، Streak، شارات، Confetti، وخريطة تحدٍّ.

## 🧠 المحرك التحليلي

**8 صفات (Traits):**
`Target Drive · Persistence · Resilience · Discipline · Learning · Coachability · Accountability · Commitment`

المنظومة تفصل صراحةً بين ثلاثة أرقام مختلفة (كما في التصوّر الأصلي):

| الرقم | معناه |
|---|---|
| **PERFORMANCE** | ماذا يبيع الموظف فعلياً (% الهدف، الحضور، التأخيرات، تقييم المدير) |
| **DNA** | أنماط عمله المستخرجة من إجاباته |
| **MATCH** | مدى تشابه المرشح مع أنماط الموظفين الناجحين |

### ما الذي يحسبه المحرك
- **DNA Profile** لكل موظف/مرشح (0–100 لكل صفة + Overall).
- **Group Centroids**: متوسط STRONG / MEDIUM / LOW + **Company Sales DNA**.
- **AI Pattern Discovery**: أي صفة تفصل فعلياً بين الأقوياء والضعفاء (Δ separation) → **أوزان تلقائية** تتغير حسب بيانات الشركة، لا أوزان ثابتة مسبقاً.
- **Question Power**: لكل سؤال متوسط الأقوياء مقابل الضعفاء → أسئلة قوية تنبؤياً وأخرى ضعيفة مرشّحة للاستبدال.
- **Candidate Match** = 45% تشابه مع الأقوياء + 40% جودة البروفايل الموزونة + 15% ابتعاد عن بروفايل الضعفاء.
- **Similar Employees**: أقرب الموظفين للمرشح حسب أنماط العمل فقط.
- **Consistency Score**: أسئلة «مرآة» (`mirror`) بصياغات مختلفة عبر المرحلتين — تناقض ⇒ 🚩.
- **Flags & Signals**: دراسة، خطة دراسة، عمل آخر، تعارض ساعات، مواصلات، تنقّل وظيفي، صفات منخفضة، تناقض.
- **Manager Summary + Interview Questions**: ملخّص لغوي وأسئلة مقابلة مخصّصة لكل مرشح حسب إشاراته الحمراء ونقاط ضعفه.
- **Prediction Accuracy**: متابعة 30/90/180 يوماً بعد التوظيف ومقارنة التنبؤ بالأداء الفعلي.

> ⚠️ **بدون فلترة أوتوماتيكية نهائية.** المرشح بتطابق 54% يُعرض كـ `LOW MATCH` مع تنبيه للمدير — والمدير وحده يقرر الفتح أو الإيقاف.

## 📚 بنك الأسئلة

- **78 سؤالاً بالعربية** موزعة على 7 مستويات و8 صفات، بثلاث درجات صعوبة.
- كل إجابة لها **درجة (0–100)**، وبعضها يحمل **Flag** أو **Follow-up تكيّفي** (`fu`).
- **Adaptive**: من يقول «لديّ دراسة» يحصل تلقائياً على سؤال متابعة عن ساعات الدراسة.
- **Randomization**: ترتيب الأسئلة والإجابات يتغيّر لكل مستخدم، والأسئلة تُسحب من Pool أكبر — يصعب تمرير «الإجابات الصحيحة» بين المرشحين.
- **Mirror pairs**: أسئلة تقيس نفس الصفة بصياغة مختلفة لقياس الاتساق.

الأسئلة كلها مرئية وقابلة للمراجعة داخل تبويب **بنك الأسئلة** في كونسول المدير (مع درجات كل إجابة وقوّتها التنبؤية).

## ⚙️ ملاحظات تقنية

- **البيانات محلية**: كل شيء في `localStorage` (نسخة عرض/Demo). للإنتاج يلزم Backend + قاعدة بيانات + صلاحيات حقيقية (الـ PIN الحالي ليس أمناً حقيقياً).
- **الملخّص والأسئلة المقترحة** يولّدهما محرّك قواعد داخلي (Rule-based) وليس نموذج لغوي خارجي — لا يخرج أي بيانات من المتصفح.
- **الواجهة**: عربية/عبرية (RTL) مع مبدّل لغة، والأسئلة بالعربية دائماً.
- **Mobile-first**: سؤال واحد بالشاشة، أزرار كبيرة، بدون تمرير طويل.
